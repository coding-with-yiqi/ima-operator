# ima 客户端操作

macOS 实测 2026-11-06。先用 API 定位与备份，再调用宿主 `mcp__cua_repl.js`。本文件不替代工具当次返回的文档。

## 少调用、少输出

首次调用单独 `let ima = await cua.getApp("com.tencent.imamac");`，不要附加动作。上下文压缩后先 `await cua.rewriteDocumentation();`。默认 `getAXState()` 返回差异；需要完整定位状态才用 `disableDiffing:true`。

```javascript
// 已绑定 app；index 来自刚观察到的状态。
await ima.click(index);
await ima.getAXState();
```

已验证的批次可在一个调用里按清单循环：读新状态 → 唯一匹配 → 动作 → 读新状态。使用 `{emit:false}` 保留状态在运行时，只输出相关行和计数；遇到多匹配、标题不符、弹窗变化或用户切换界面立即退出循环。不要预存元素序号、盲点坐标或并发操作同一应用。AX 足够时不截图；截图后需重新读完整 AX 再用索引。最终观察成功后，下一次 CUA 调用只提交 `completion_summary`。

## 原位替换正文：已实测

1. 从源路径映射取得同一 `note_id/media_id`。API 备份纯文本、富文本 JSON、来源链接和散列；检查云端人工改动，合并后形成待写完整稿。确认 UTF-8、云端链接和恢复材料可读。
2. 打开对应笔记，核对标题和界面的 `docid`，选中当前正文编辑区。本机 `selectText()` 曾选区偏移，不把成功返回当作选对文字。
3. 正确正文区 `super+a`、`BackSpace`；观察零字且 docid 未变，再 API 回读同一笔记确为空。只有此时才用 `append_doc` 写完整最新 Markdown，防止整篇重复追加。
4. 本机清空会保留空首段。写回后重新观察编辑区，`super+Home`、`Delete` 去掉空首段并触发标题保存；不盲发到其他页面。API 核对标题，避免“未命名笔记”。长标题可能自动省略，保留完整逻辑标题与实际显示标题。
5. 回读原 KB 条目的 `notebook_ext_info.notebook_id`、笔记全文与富文本链接。全文与来源逐项核对，不能只看前 100 字；忽略排版不应吞掉有意义的标点、公式或代码差异。原 ID 与目录数量保持不变，写回映射。

清空后写入失败：先回读判断是否部分成功，恢复该笔记。恢复原 Markdown 前确认空正文；富文本或人工编辑不能由源稿恢复时，用客户端撤销并核对，不把纯文本当完整格式恢复，不创建副本掩盖失败。

## 旧文件迁成可编辑笔记：已实测

只读 Markdown 阅读器有“转存为笔记”；也可由 API 从完整稿创建笔记后 `media_type=11` 关联到原目录。验证全文、链接、标题与映射后，该源路径以后只编辑这一篇。旧版本备份与清理独立执行：先迁移验收，再清理。

## 删除：已实测

1. 按 [去重流程](dedup.md) 确定对象；保存 ID、精确标题、父目录、旧正文 SHA256、完整原件与保留版本。分清知识库条目与个人笔记：本任务实测是删除库内旧文件，不能推断同时删掉笔记本原件。
2. 删除前刷新盘点和目标原文，与备份散列比较。有人工修改、对象消失或新增版本时重算，不沿用过期清单。
3. 正确库与目录，对精确旧标题右键 → “删除”，观察弹窗。本机提示“删除后内容将从知识库移除，且不可恢复”；按 CUA 当前规则，在清单和备份就绪后取得执行时确认。说明要求来自 CUA 永久删除规则；同一清单已有此确认可连续执行，不重复问每篇。
4. 确认后逐项操作并观察。结束后 API 全量盘点：消失 ID 集合恰好等于批准集合；其他 ID、标题、父目录不变；保留笔记正文散列不变。数量减少本身不够证明正确。
5. 更新映射、回执和本地备份索引。已不存在的项记为已处理，不能因标题相同去删另一个 ID。

## 建库、建文件夹、重命名、移动

当前网关无这些接口，通过客户端观察实际入口。这组流程尚未逐项独立实测，不能猜菜单名。先定位唯一源对象及目标路径，再执行；之后 API 取得真实新 ID 或核对原 ID 的标题、父目录。建文件夹与建笔记本分开，移动不应创建副本。涉及扩展访问或共享权限时按当前工具规则处理授权。
