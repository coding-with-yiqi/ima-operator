# 自动接入流程

由当前 Agent 负责闭环，Python 只处理本地检测、官方包安装和 API 验收；连接器与界面操作由宿主执行。不要要求用户先选择平台、填安装目录或重复配置已可用的密钥。

## 入口

先复用上下文中已有的连接、技能与配置线索。用户要求安装本项目时，检查宿主技能目录和当前项目是否已有 `ima-operator`；已有则从该目录执行，缺少才按对应宿主导入本项目，不反复 clone。然后运行：

```bash
python3 <技能目录>/scripts/bootstrap.py --apply
```

Python 命令不存在时，先检查该宿主可用的 Python 3.9+（例如 Windows 的 `python`/`py -3`），使用已安装解释器。确实缺少才按宿主的官方安装方式补齐。

检测依据是当前宿主明确身份、父进程名称、活动会话标记，**不能根据电脑里安装了哪个 App 就判定正在用它**。宿主身份在上下文中明确但脚本无法识别时，Agent 自行传 `--agent workbuddy|codex|claude-code|openclaw|other`，无需问用户。默认无法识别时走通用 API 路径。

任务需要笔记创建、追加等 OpenAPI 能力时加 `--need api`。仅使用 WorkBuddy 连接器时保持默认，不为一次读取额外安装 API 技能或索要密钥。

已有官方包在非标准位置时，根据现有项目配置传一次 `--official-dir <实际路径>`；随后脚本记住路径，操作工具自动读取，不再要求 export。不要全盘扫描账号文件或复制 WorkBuddy 内部 token。

## WorkBuddy 分支：宿主自动执行

脚本返回 `host_connector_check_required` 后，立即使用宿主已有的连接器管理/发现工具检查 ima，工具不足再用已授权 Computer Use：

1. 已连接且本次启用：直接只读列库并读取一篇已知资料；成功即复用。
2. 已授权但关闭：仅为当前任务启用，再只读验证，不重新安装或扫码。
3. 未连接：Agent 打开官方 ima 连接入口，准备到授权页；仅扫码/账号确认交给用户。完成后自动继续验证。
4. 明确授权过期：走该连接器的重新连接流程；网络错误或无权限不能当作密钥失效。
5. 当前任务还需要 OpenAPI：继续 `--agent workbuddy --need api --apply`；完整官方包若已安装，发现实际路径后传给脚本复用。新下载的官方包无需重复导入；由本技能按返回路径读取官方说明即可调用 API，用户需要独立 Skill 菜单时才导入一次。

Python 不声称已核实 WorkBuddy 连接器状态，也不写它的私有配置。当前官方操作入口见 [WorkBuddy 指引](install-workbuddy.md)。无法通过宿主工具操作时，才给用户最短的实际缺项，不能假报已连接。

## API 分支：脚本自动执行

脚本会：

- 查当前显式路径、已记住路径、各 Agent 的标准技能目录；解析符号链接去重，复用完整官方包，不降级、不重复安装。
- 缺少时从 ima 官方地址下载核验过的包，验证 SHA256、解压到临时目录、检查完整性，再放入目标目录；不覆盖旧目录。
- 将实际官方路径保存在本机 `~/.config/ima/operator.json`。不含凭证；再次运行不重写同一配置。
- 优先用现有凭证文件；文件缺失而当前环境已有完整且不冲突的 ima 凭证时，自动保存到本机。POSIX 权限设为 0600，Windows 访问控制沿用用户目录 ACL，宿主应确认该目录不共享。文件与环境不一致时保留原值，绝不混配账号。
- 检查 Node.js 18+；前置条件齐备后发起一次只读 API 请求。`ready` 证明本次鉴权及连接通过，具体目标库仍须在业务步骤核对。

`--apply` 是本地补齐开关。省略时只输出检测和计划，不安装、不保存凭证、不调用 API。

## 有下一步就继续，不交给用户抄命令

- `ensure_node_18_via_host`：先查当前宿主已有 Node 与 PATH；可复用则修正本次执行环境。确实缺少时，Agent 用官方来源或已安装可信包管理器补齐所需运行时，再重跑。避免替换其他项目正在使用的版本。只有管理员权限、许可确认等实际要求需要人处理时才交接。
- `credentials_available_in_environment`：若当前是检测模式，用 `--apply` 自动复用，不问用户重填。
- `credentials_missing`：先完成其余本地准备，再打开官方凭证入口并提供安全的本机凭证保存位置；只让用户完成首次凭证提供。不要让用户在普通对话贴密钥，不自行重置。
- `credential_conflict`：根据当前已明确的账号与配置排查，保留原值；确实无法判断账号时，只问这一项。
- `inspect_existing_skill` / `repair_explicit_skill_path`：检查返回路径、版本和缺文件。先寻找健康副本复用；确定残缺安装后备份并按同版本只补缺失文件，不创建多份并存来掩盖错误。
- `setup_failed`：看结构化错误；下载完整性失败不执行包，官方 `-200` 依官方更新流程处理，不循环下载旧版本。
- `blocked_execution_network`：保留本地成果，遵守环境边界。权限恢复后从缺项续跑，不能绕过。

最终只回报“复用了什么、补齐了什么、是否验证通过、确实仍需用户做的唯一动作”。完整路径和官方文档只按需读取。第一次完成后再运行，安装、凭证和路径配置应均无变化；只读鉴权可再次执行。
