# ima 的 20 个主要使用场景

依据：社群周报、主题专栏、事实核查、原位迁移与重复清理等实际工作。标记“已实测”指作者的维护流程已有回执，公开包不含私人原文；“官方支持”指接口文档支持但此场景未独立验收；“待实测”为可执行路线，需当次客户端验证。不是 20 项均已实测。

## 01 找到正确知识库

“把资料放到团队知识库。”先本地映射，再官方库搜索和详情；核对完整名称、已有文件、可访问范围。一次取当前 ID，后续复用。验收：唯一目标；库名相同多结果时不猜。**已实测**。

## 02 搜到已有答案

“群里之前讲过 Agent 记忆吗？”先搜个人知识库，再用 `search_knowledge` 搜目标 ima 库，只取命中摘要，选中后读原文。验收：答案保留来源与日期，找不到不写成“库里绝对没有”。**搜索/读取已实测**。

## 03 读取某篇完整材料

“打开这份事实核查说明。”`get_media` 判断类型；笔记读纯文本，文件下载官方返回的原文。长文存本地后定向查段落。验收：读到原文、类型正确；摘要不能冒充全文。**已实测**。

## 04 新建可持续编辑的笔记

“把这篇讲义建成 ima 笔记。”查映射和同名后 `create_note/import_doc`，正文首行放标题。验收：返回新 note_id，全文与来源链接完整，重复运行不再新建。**已实测**。

## 05 把已有笔记放进指定知识库

“放到每周新闻目录。”先定位真实目录，再 `add_note_to_knowledge`，只关联一次。验收：media_id 指向原 note_id，目录正确；日后改笔记不再上传副本。**已实测**。

## 06 生成每周新闻

“更新上一完整周。”本地按北京时间周一至周日整理、核对来源；新周创建笔记，旧周补同步改原 note_id。验收：一个周次一篇有效文档，本周未结束明确标注。**已实测**。

## 07 持续整理随机分享专栏

“把新分享合进编程、教育等主题。”本地只处理新增条目，保留日期、具体内容与原文定位，更新同一主题笔记。验收：事实、经验、活动分清，未变化主题跳过。**已实测**。

## 08 更新事实核查说明

“把已确认的信息修正进去。”先查个人库和可靠一手来源，再原位改说明，保留修订日期与有效链接。验收：原 note/media ID 不变，来源仍可定位。**已实测**。

## 09 原位修订，不生成重复稿

“这一段改了，直接改原文。”小改走当前编辑器；完整替换走备份 → CUA 清空 → API 确认空 → 写回 → 标题及全文验收。验收：同一 ID、数量不增、人工修改保留。**已实测**。

## 10 向已有笔记追加新内容

“在这篇结尾加上今天补充。”明确 note_id，检查本段是否已写过，再 `append_note`。验收：原正文保留，新段仅一次；网络超时先回读再决定重试。**追加接口已实测**。

## 11 迁移只读文件为可编辑正文

“这份 Markdown 今后要经常改。”备份原件，转存或 API 创建笔记并关联原目录；全文、链接核验后更新映射。验收：源路径只指一篇可编辑正文；旧文件另按清单清理。**已实测**。

## 12 跳过没有变化的文档

“每周自动同步，但不要重复上传。”比较源和云端散列，只处理内容变化。判定和摘要在脚本内完成。验收：未变项写请求为零，回执区分跳过与更新。**已实测**。

## 13 查找疑似重复内容

“库里有没有同一篇传了几遍？”一次盘点后本地按标题、源键和同类型散列分组，只读候选正文。验收：输出候选与理由，不把同名不同内容自动删除。**已实测**。

## 14 合并多份修订版

“把旧稿、新稿、补充稿合成一篇。”根据映射和全文差异保留独有内容，合进固定笔记，保留版本关系。验收：最新版完整、来源不丢；旧版先备份。案例：13 篇正文对应 37 个旧文件。**已实测**。

## 15 删除指定旧文件

“清理这份清单。”备份及散列核验 → CUA 取得本次不可恢复删除确认 → 精确逐项删 → API 差集验收。验收：批准集合全部消失，其他对象保留。案例：37 项删除，意外删除 0。**已实测**。

## 16 建库、建目录和整理位置

“新建一个课程库，按课程与答疑分目录。”当前官方工具无对应创建/移动接口，观察客户端入口操作；API 回读新目录 ID。验收：路径和父目录正确，无额外副本。**待实测**。

## 17 上传课程原件

“把课件 PDF 和 Markdown 原稿放进去。”官方预检、查同名、COS 上传、关联入库；不转码改变原件。验收：原件 SHA256、标题、目录匹配；上传和解析分开报告。**Markdown 上传已实测；其他格式当次验收**。

## 18 收藏网页和公众号文章

“把这几个来源链接收进库。”先按 URL 查重，`import_urls` 每批 1–10 个，逐项检查结果。验收：目标目录和每条导入结果明确，链接失效如实记录。**官方支持，未独立实测**。

## 19 备份、导出和恢复

“修改之前留一份能恢复的。”文件保存原始字节，笔记保存纯文本、富文本、链接及源 Markdown；脚本计算 SHA256、打包验完整。验收：每个备份能读且与云端一致；恢复另核同一对象及格式。**备份已实测；完整格式恢复须当次验收**。

## 20 同步出错后续跑并核验可检索性

“别只报告失败，把剩下的接着做完。”区分网络权限、业务码、目标 ID 变化、标题异常；从回执缺失步骤续做。已写成的稿不重传。上传回读通过后，如任务要求可问答，再用搜索/客户端验证目标内容。验收：待办归零或明确剩余项；未实测索引不报已可检索。**故障续跑已实测，全文索引未独立验收**。
